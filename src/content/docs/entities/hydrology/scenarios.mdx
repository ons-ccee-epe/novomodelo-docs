## What the model decides

Nothing about the scenarios themselves: they are data, drawn and evaluated by the model. In the forward pass the model follows a single trajectory, one node per stage along the path it visits. In the backward pass it evaluates every opening of each node at the states visited by the forward pass, and builds the cuts from them.

## What you provide

- The number of openings of each stage (`num_openings`), required on the plain stage chain and wherever the openings are generated.
- The method that generates the openings of each stage (`sampling_method`), which can vary by stage.
- The forward-pass noise source of each stochastic class (inflow, load, non-controllable sources), in the run configuration. When not set, every class draws from the opening tree.
- Optionally, external scenarios, a supplied opening tree, or the inflow history for replay.
- Optionally, spatial correlation between the plants of the same group, and a seed for the opening tree.

## How the forward pass chooses its noise

The sampling scheme selects the noise that the forward pass uses at each stage, separately for each class. There are four.

- **In-sample.** The default. The forward pass draws an opening from the same opening tree that the backward pass uses.
- **Out-of-sample.** It draws fresh noise from the applied model, with a seed independent of the opening tree's. Its forward costs estimate the cost of the policy under the model, not under the tree.
- **External.** It reads the scenarios you supply.
- **Historical.** It replays the inflow record. It exists for the inflow class only.

The backward pass is not affected: it always evaluates all the openings of the tree. With the external and historical schemes, the forward trajectories follow the external or historical law while the cuts and the lower bound are built on the opening tree, so the gap compares two different problems and need not close.

## How the openings are generated

The method of each stage decides how the tree is filled, independently of the sampling scheme.

- **Plain Monte Carlo.** The default. Independent standard-normal components, equiprobable openings.
- **Latin hypercube, scrambled Sobol and scrambled Halton.** Stratified or low-discrepancy samples of the same distribution.
- **Selective.** The openings come from a tree you supply, and Novomodelo generates none.
- **Historical residuals.** Each opening carries the standardized inflow noise of one window of the historical record, which already embeds the correlation between plants.

The correlation between plants of the same group is applied after the draws in the first four methods.

## Nodes and transitions

By default the policy graph is a chain with one node per stage. Declaring nodes explicitly lets a stage hold several. A transition is a directed edge to a node exactly one stage later, weighted by a probability. Two probabilities stay distinct: the one on the edge says which child node a trajectory moves to, and the one on the openings says which realization is evaluated once the node is reached.

An enumerated pass, with no sampling, visits every node and every path of a finite graph, so its bounds are those of the declared tree. It suits short horizons and trees that branch at few stages.
