O parâmetro de distribuição de trabalho da simulação backward do Novo Modelo fica
no bloco `training.parallelism` do `config.json`. Esta aba mostra como o
escalonador é escolhido; a simulação backward e o modelo de execução dentro dos
quais o escalonador distribui o trabalho permanecem nas seções de metodologia acima
([§3.2 Simulação Backward](/pt-br/math/sddp-algorithm#32-simulacao-backward),
[§3.4 Modelo de Execução e Considerações de Desempenho](/pt-br/math/sddp-algorithm#34-modelo-de-execucao-e-consideracoes-de-desempenho)).

### `training.parallelism` — Configuração do Escalonador da Simulação Backward

O escalonador decide como o trabalho da simulação backward é dividido entre os
workers: por padrão, um estado visitado por unidade de trabalho, ou um par
`(trial point, opening block)` (estado visitado, bloco de aberturas) por unidade de
trabalho com `by_node`. Com qualquer dos dois escalonadores, o conjunto de cortes e
o limite inferior do treinamento (training) não dependem do número de workers nem
da ordem em que os workers assumem as unidades. Os dois escalonadores encadeiam de
forma diferente as aberturas de um estado visitado; assim, uma resolução pode partir
de outra base
([Aproveitamento de base do PL §2](/pt-br/math/lp-warm-start#2-repositorio-de-bases-por-cenario-no)) e,
quando um PL do estágio tem várias soluções ótimas, terminar em outra delas; os
cortes dos dois podem então diferir. O exemplo seleciona `by_node` com quatro
aberturas por bloco:

```json
{
  "training": {
    "parallelism": {
      "backward_scheduler": { "method": "by_node", "block_size": 4 }
    }
  }
}
```

[`training.parallelism`](/pt-br/running/configuration/#trainingparallelism) lista os
métodos, campos, valores padrão e erros de carregamento;
[Escalonamento por nó](/pt-br/running/performance/#escalonamento-por-no) explica quando
usar `by_node` e sua interação com o método de seleção `dynamic`.
