O pacote `novomodelo` é o binding Python do solver Novo Modelo (`import novomodelo`). Esta página lista a assinatura, o comportamento, o formato de retorno e as classes de exceção levantadas de cada nome público do pacote `novomodelo`, de `novomodelo.run`, `novomodelo.io`, `novomodelo.results`, `novomodelo.errors` e `novomodelo.schema`, além dos campos das classes de dados em `novomodelo.model` e dos dicts de resultado tipados em `novomodelo._types`. Para instalar o pacote, veja [Instalação](/pt-br/getting-started/installation/); para uma primeira sessão guiada, veja o [Guia rápido em Python](/pt-br/getting-started/python-quickstart/).

Convenções usadas em todas as entradas:

- Os caminhos aceitam `str` ou `pathlib.Path`.
- O pacote é executado em um único processo. Ele nunca inicializa o MPI e libera o GIL (o global interpreter lock do Python) enquanto o solver calcula.
- Os diagnósticos de aviso são gravados no descritor de arquivo 2. `contextlib.redirect_stderr` não os captura.
- Cada cabeçalho é o nome qualificado de um símbolo e é a âncora dessa entrada (`#novomodelostudytrain` para `novomodelo.Study.train`).

### `novomodelo.Study`

```python
class Study:
    def __init__(
        self,
        case_dir: str | Path,
        output_dir: str | Path | None = None,
        threads: int | None = None,
        config_overrides: Mapping[str, Any] | None = None,
    ) -> None: ...
```

Um estudo carregado e reutilizável. A construção carrega o caso, resolve a configuração, executa o pré-processamento estocástico e dos modelos hidrelétricos e grava `training/scaling_report.json`, `training/model_provenance.json` e `training/hydro_models.json` (além das exportações estocásticas, quando habilitadas) em `output_dir`. A validação ocorre aqui: um caso ou uma configuração que falha na validação levanta exceção no construtor, de modo que um `Study` construído é válido.

**Parâmetros**

- `case_dir`: o diretório do caso.
- `output_dir`: onde os resultados são gravados. Padrão: `<case_dir>/output`.
- `threads`: threads de trabalho para o treinamento (training) e a simulação, no mínimo 1. `None` executa em uma thread, e não em todos os núcleos. O valor é armazenado para `train` e `simulate` e não é usado durante a carga.
- `config_overrides`: um mapeamento plano de chaves com pontos, mesclado em profundidade em `config.json`. `{"training.enabled": False}` define apenas essa chave e mantém as chaves irmãs. Um valor aninhado sob uma única chave substitui o objeto inteiro nessa chave; assim, `{"training": {"enabled": False}}` descarta todas as demais chaves de `training` e falha na validação. Uma chave desconhecida falha na validação. Para as chaves, veja [Configuração](/pt-br/running/configuration/).

**Levanta**

- `OSError` (embutida) quando `case_dir` não existe, antes de qualquer processamento.
- `ValueError` (embutida) quando `threads` é `0`, ou quando `config_overrides` tem uma chave que não é `str` ou um tipo de valor não suportado.
- `novomodelo.errors.ValidationError` para falha de sobrescrita, de interpretação ou de leitura da configuração; para arquivo do caso ausente ou ilegível; para falha de esquema, de interpretação ou de restrição nos dados do caso; para um `policy.path` recusado; e para falha de preparação por entrada inválida, como um modelo estocástico não suportado (`no valid historical windows found`).
- `novomodelo.errors.CaseIoError` quando a gravação de um desses arquivos falha, por exemplo em um `output_dir` sem permissão de escrita.
- `novomodelo.errors.SolverError` para falha do solver ou falha interna durante o pré-processamento ou a construção.

#### `novomodelo.Study.train`

```python
def train(
    self,
    on_iteration: Callable[[dict[str, Any]], Any] | None = None,
) -> Policy: ...
```

Treina uma política PDDE (SDDP) sobre a preparação em memória do estudo e retorna um [`novomodelo.Policy`](#novomodelopolicy). A chamada grava a política em `<output_dir>/<policy.path>` (padrão `policy/`) e os artefatos do treinamento em `training/`. O GIL é liberado enquanto o solver calcula; o callback é executado em uma thread separada, que só obtém o GIL nas fronteiras entre iterações.

**Parâmetros**

- `on_iteration`: chamado uma vez em cada fronteira entre iterações com um dict contendo `kind`, `iteration`, `lower_bound`, `upper_bound`, `gap` e `wall_time_ms`. `gap` é o gap relativo bruto, não multiplicado por 100. Um retorno verdadeiro solicita uma parada cooperativa em uma fronteira de iteração posterior; a parada é assíncrona, de modo que a iteração em que a execução termina não é fixa. Uma exceção levantada pelo callback é relançada sem alteração depois que os artefatos são gravados.

Uma parada solicitada pelo callback, ou uma exceção levantada por ele, encerra a execução com `convergence.termination_reason` igual a `"graceful_shutdown"` e `status` igual a `"partial"` em `training/metadata.json`, a menos que os critérios de parada ou o limite de iterações também a tenham encerrado nessa iteração; veja [`training/metadata.json`](/pt-br/reference/output/metadata/#trainingmetadatajson).

**Retorna**: um [`novomodelo.Policy`](#novomodelopolicy). Com `training.enabled` igual a `false`, `train` retorna uma política com zero iterações e sem cortes; `simulate` a rejeita. Nesse caso, carregue uma política treinada com `load_policy`.

Uma segunda chamada a `train` no mesmo `Study` é executada sobre uma preparação que já contém os cortes da primeira chamada, portanto não é um treinamento do zero. No caso-modelo 1dtoy, a segunda chamada levanta `SolverError` (`basis row count mismatch`).

**Levanta**

- `novomodelo.errors.SolverError` para falha de inicialização do solver ou falha de treinamento classificada pelo solver.
- `novomodelo.errors.ValidationError` para diretório de política anterior ausente em partida a quente (warm-start) ou retomada (`Policy directory not found: ...`), e para entrada de fronteira ou de treinamento recusada.
- `novomodelo.errors.PolicyIncompatibleError` quando o checkpoint de partida a quente ou de retomada em `policy.path` não atende ao [Contrato de carga da política](/pt-br/running/policy-management/#contrato-de-carga-da-politica), quando um checkpoint de `policy.boundary` foi gravado por outro software ou outra versão, ou quando o `manifest.bin` de um checkpoint está ausente ou não pode ser decodificado.
- `novomodelo.errors.CaseIoError` quando a gravação da política ou de um artefato do treinamento falha; uma falha na gravação de checkpoint periódico levanta `FileNotFoundError`, `CaseIoError`, `novomodelo.errors.OutputError` ou `ValidationError`, conforme a causa.
- `novomodelo.errors.InternalError` quando a thread do callback entra em pânico (panic).
- Qualquer exceção levantada pelo callback, e `KeyboardInterrupt`, relançadas depois que os artefatos são gravados.

#### `novomodelo.Study.load_policy`

```python
def load_policy(
    self,
    output_dir: str | Path | None = None,
) -> Policy: ...
```

Lê um checkpoint da política de `<output_dir>/<policy.path>/` e retorna um [`novomodelo.Policy`](#novomodelopolicy) que `simulate` aceita da mesma forma que uma política treinada. O checkpoint é sempre verificado em relação à dimensão do estado, ao número de estágios e ao manifesto de entidades terminais do estudo.

**Parâmetros**

- `output_dir`: o diretório que contém a política. Padrão: o `output_dir` do estudo.

**Retorna**: o [`novomodelo.Policy`](#novomodelopolicy) carregado.

**Levanta**

- `novomodelo.errors.ValidationError` quando o diretório da política está ausente (`Policy directory not found: ...`).
- `novomodelo.errors.PolicyIncompatibleError` quando o checkpoint não pode ser lido, decodificado ou reconstruído, ou quando a validação da política o rejeita.
- `novomodelo.errors.CaseIoError` quando um arquivo do checkpoint não pode ser aberto.

#### `novomodelo.Study.simulate`

```python
def simulate(
    self,
    policy: Policy,
    output_dir: str | Path | None = None,
) -> dict[str, Any]: ...
```

Executa a fase de simulação com `policy` e grava os artefatos de `simulation/`. Cada chamada grava um conjunto novo de saídas, e uma mesma política pode alimentar chamadas repetidas.

**Parâmetros**

- `policy`: um [`novomodelo.Policy`](#novomodelopolicy) obtido de `train` ou `load_policy`.
- `output_dir`: onde o diretório `simulation/` é gravado. Padrão: o `output_dir` do estudo.

**Retorna**: `{"n_scenarios": int, "completed": int}`, por exemplo `{'n_scenarios': 10, 'completed': 10}`.

**Levanta**

- `novomodelo.errors.SolverError` quando a política não tem cortes (`Policy has no cuts to simulate; when training is disabled, call Study.load_policy() to load a trained policy before simulate()`), ou em falha de inicialização do espaço de trabalho da simulação.
- `novomodelo.errors.SimulationError` para falha da simulação.
- `novomodelo.errors.CaseIoError` para falha do gravador.
- `novomodelo.errors.InternalError` quando a thread de trabalho entra em pânico (panic).

### `novomodelo.Policy`

```python
class Policy: ...
```

Uma política treinada ou carregada: os cortes de Benders que aproximam o custo futuro de cada estágio, juntamente com os dados de que `novomodelo.Study.simulate` precisa. A classe não tem construtor Python; `novomodelo.Policy()` levanta `TypeError` (`cannot create 'builtins.Policy' instances`). Obtenha uma instância a partir de [`novomodelo.Study.train`](#novomodelostudytrain) ou [`novomodelo.Study.load_policy`](#novomodelostudyload_policy).

Todo argumento `stage` é numerado a partir de 0: o estágio `t` da numeração a partir de 1 usada na metodologia é `stage = t - 1`.

`evaluate` e `cut_matrix` leem o conjunto de cortes em memória, que armazena termos independentes e coeficientes na escala de custo do solver: unidades monetárias divididas pelo `cost_scale_factor` do conjunto (`modeling.cost_scale_factor`, `1000000.0` por padrão). O checkpoint armazena os mesmos valores escalonados, de modo que [`novomodelo.results.load_policy`](#novomodeloresultsload_policy) também os retorna. Multiplique por `cost_scale_factor` para obter unidades monetárias. `final_lower_bound` e `final_upper_bound` estão em unidades monetárias. Para a conversão, veja [Canonicalização da escala de custo](/pt-br/running/policy-management/#canonicalizacao-da-escala-de-custo).

#### `novomodelo.Policy.iterations`

```python
@property
def iterations(self) -> int: ...
```

O número de iterações de treinamento concluídas. Uma política obtida de `load_policy` reporta o `completed_iterations` do checkpoint; uma política com treinamento desabilitado reporta `0`.


O limite inferior final, em unidades monetárias. Uma política obtida de `load_policy` reporta o limite inferior final registrado no checkpoint; uma política com treinamento desabilitado reporta `0.0`.

#### `novomodelo.Policy.final_upper_bound`

```python
@property
def final_upper_bound(self) -> float: ...
```

O [limite superior](/pt-br/math/upper-bound-evaluation/) médio final, em unidades monetárias. Uma política obtida de `load_policy` reporta o limite superior registrado no checkpoint (o valor da última iteração do treinamento, e não o melhor valor acumulado), ou `inf` quando o checkpoint não registra nenhum; uma política com treinamento desabilitado reporta `inf`.

#### `novomodelo.Policy.evaluate`

```python
def evaluate(self, stage: int, state: Sequence[float]) -> float: ...
```

Avalia a função de custo futuro em `state`: o máximo, sobre os cortes ativos do estágio, de `intercept + coeffs · state`. O valor está na escala de custo do solver, e não em unidades monetárias (veja [`novomodelo.Policy`](#novomodelopolicy)). Um estágio sem corte ativo retorna `float('-inf')`; o último estágio do caso 1dtoy não tem nenhum.

**Parâmetros**

- `stage`: o índice do estágio, a partir de 0.
- `state`: o estado de entrada, um float por dimensão do estado da política (`1` para o caso 1dtoy).

**Retorna**: o valor do custo futuro como `float`.

**Levanta**

- `IndexError` (embutida) quando `stage` é maior ou igual ao número de estágios (`stage 4 out of range (policy has 4 stages)`).
- `ValueError` (embutida) quando `state` tem comprimento errado (`state has length 2, expected 1 (policy state dimension)`).
- `OverflowError` (embutida) quando `stage` é negativo.

#### `novomodelo.Policy.cut_matrix`

```python
def cut_matrix(self, stage: int) -> tuple[Any, Any]: ...
```

Retorna os cortes ativos de um estágio como dois arrays NumPy, em ordem crescente de slot. Leia o corte `k` como `θ ≥ intercepts[k] + coeffs[k] · state`. Os coeficientes são os valores armazenados, sem negação. Os valores estão na escala de custo do solver, e não em unidades monetárias (veja [`novomodelo.Policy`](#novomodelopolicy)).

**Parâmetros**

- `stage`: o índice do estágio, a partir de 0.

**Retorna**: `(intercepts, coeffs)`, dois arrays `float64` com formatos `(n_cuts,)` e `(n_cuts, dim)`, em que `dim` é a dimensão do estado da política. Um estágio sem corte ativo retorna os formatos `(0,)` e `(0, dim)`.

**Levanta**

- `IndexError` (embutida) quando `stage` é maior ou igual ao número de estágios.
- `OverflowError` (embutida) quando `stage` é negativo.
- `ImportError` (embutida) quando o NumPy não está instalado.

### `novomodelo.write_policy_checkpoint`

```python
def write_policy_checkpoint(
    path: str | Path,
    stage_cuts: Sequence[Mapping[str, Any]],
    metadata: Mapping[str, Any],
    stage_bases: Sequence[Mapping[str, Any]] | None = None,
    stage_states: Sequence[Mapping[str, Any]] | None = None,
    inflow_lag_depth: int | None = None,
) -> None: ...
```

Grava um checkpoint da política em `path` a partir de dicts Python simples. `stage_cuts`, `metadata`, `stage_bases` e `stage_states` têm os formatos das chaves que [`novomodelo.results.load_policy`](#novomodeloresultsload_policy) retorna, de modo que um checkpoint carregado faz o percurso de ida e volta; as chaves de um resultado carregado que o gravador não lê são ignoradas. `stage_bases` e `stage_states` são vazios por padrão. Toda entrada de `stage_cuts` exige um `cost_scale_factor`, finito e positivo: os termos independentes e coeficientes da entrada estão nas unidades desse fator, de modo que uma política elaborada em unidades monetárias informa `1.0`. O `cost_scale_factor` de `metadata["producer"]` serve apenas como procedência e nunca substitui um fator ausente do conjunto. O checkpoint sempre registra a versão do novomodelo em execução; as chaves `software`, `software_version` ou `novomodelo_version` em `metadata` são ignoradas. Para os formatos dos dicts, veja [Gravar um checkpoint](/pt-br/running/policy-management/#gravar-um-checkpoint), [Exemplo de ida e volta](/pt-br/running/policy-management/#exemplo-de-ida-e-volta) e [Validação da entrada](/pt-br/running/policy-management/#validacao-das-entradas).

`inflow_lag_depth = N` com `N > 0` reserva `N` slots de estado de tendência hidrológica por usina com reservatório em cada estágio e posiciona os `inflow_lag_coefficients` de cada corte em suas posições `(hydro, depth)`. Use-o para elaborar uma política de fronteira para um caso convertido que não tenha modelo PAR(p) do qual inferir a profundidade. Ausente ou `0`, o checkpoint é idêntico a um gravado sem o argumento.

**Retorna**: `None`.

**Levanta**

- `ValueError` (embutida) quando um dict contém uma chave que não faz parte de um checkpoint da política: `active_cut_indices` em uma entrada de `stage_cuts`, `cut_id` em um corte, ou `num_cut_rows`, `num_columns` ou `num_rows` em uma entrada de `stage_bases` (`stage_cuts[0]: key 'active_cut_indices' is not part of a policy checkpoint (format 4); remove it`, indicando a posição). Essas chaves são verificadas antes da leitura de `stage_cuts` e `stage_bases`.
- `ValueError` (embutida) quando o `cost_scale_factor` de uma entrada de `stage_cuts` está ausente, não é finito ou não é positivo (`stage_cuts[{index}] (stage_id {id}): cost_scale_factor is required; the intercepts and coefficients are in the units of this factor (pass 1.0 for values in currency units)`, ou `must be finite and positive, got {value}` no lugar de `is required`).
- `ValueError` (embutida) quando o comprimento de `coefficients` de um corte difere do `state_dimension` de seu estágio, quando um corte contém `inflow_lag_coefficients` sem um `inflow_lag_depth` positivo ou, com `inflow_lag_depth` definido, quando o manifesto de um estágio não tem um bloco inicial de armazenamento ou um coeficiente de tendência hidrológica não tem slot onde ser posicionado.
- `ValueError` (embutida) quando `metadata["producer"]["basis_store_complete"]` é `True` e `stage_bases` não contém nenhuma base, ou quando o `state_history` do produtor é diferente de `None`, `"whole"` ou de um inteiro positivo (um `bool` é recusado).
- `ValueError` (embutida), com a mensagem da regra, quando os dados violam uma regra do checkpoint antes que algo seja gravado: ordem dos slots, contagem de linhas (incluindo um comprimento dos dados de estado de um estágio diferente de `count * state_dimension`), presença de contadores, datas, id repetido ou limite de tamanho ([Validação da entrada](/pt-br/running/policy-management/#validacao-das-entradas)).
- [`novomodelo.errors.ValidationError`](#novomodeloerrorsvalidationerror) (uma `ValueError`) quando `path` (no caso de um link, seu destino) ou seu irmão `.staging` ou `.previous` contém uma entrada que nenhum gravador de checkpoint deixaria ali (`refusing to write a checkpoint: ...`); nada é alterado no disco.
- Uma classe de [`novomodelo.errors`](#novomodeloerrors) mapeada a partir da falha de gravação subjacente, para qualquer outro erro, como [`novomodelo.errors.OutputError`](#novomodeloerrorsoutputerror).

## `novomodelo.run`

### `novomodelo.run.run`

```python
def run(
    case_dir: str | Path,
    output_dir: str | Path | None = None,
    threads: int | None = None,
    config_overrides: Mapping[str, Any] | None = None,
    on_iteration: Callable[[dict[str, Any]], bool | None] | None = None,
) -> RunResult: ...
```

Carrega um caso, executa o treinamento, executa a simulação quando a configuração a habilita e grava os resultados. Um único `novomodelo.Study` conduz a chamada. As fases executadas seguem a configuração, em três ramos.

**Parâmetros**

- `case_dir`, `output_dir`, `threads`, `config_overrides`: como em [`novomodelo.Study`](#novomodelostudy).
- `on_iteration`: como em [`novomodelo.Study.train`](#novomodelostudytrain).

**Retorna**: um dict com o formato [`novomodelo._types.RunResult`](#novomodelo_typesrunresult). Todas as chaves estão presentes em todos os ramos; os valores abaixo diferem por ramo.

| Ramo | `converged` | `iterations` | `lower_bound` | `upper_bound` | `gap_percent` | `simulation` |
| --- | --- | --- | --- | --- | --- | --- |
| Treinamento habilitado | `True` quando os critérios de parada encerraram o treinamento e uma regra `gap` ou `bound_stalling` foi acionada nessa iteração; `False` para qualquer outro motivo de parada | iterações executadas | limite inferior final | [limite superior](/pt-br/math/upper-bound-evaluation/) final | gap vezes 100 | o dict de resumo, ou `None` se a simulação estiver desabilitada |
| Treinamento desabilitado, simulação habilitada (somente simulação) | `False` | `0` | o limite inferior do checkpoint | o limite superior registrado no checkpoint (o valor da última iteração do treinamento), `None` se não for finito | `None` | o dict de resumo |
| Ambos desabilitados | `False` | `0` | `0.0` | `None` | `None` | `None` |

`gap_percent` é o gap relativo vezes 100; veja [Gap de otimalidade](/pt-br/math/stopping-rules/#gap-de-otimalidade). Uma execução somente de simulação carrega a política de `<output_dir>/<policy.path>/` (padrão `policy/`); veja [Modo somente simulação](/pt-br/running/policy-management/#modo-somente-de-simulacao). As chaves `stochastic`, `hydro_models` e `provenance` contêm os mesmos resumos que as propriedades de `Study`.

Um Ctrl-C durante a execução é entregue como `KeyboardInterrupt` depois que a chamada retorna ao interpretador, e não em uma fronteira entre iterações. Para encerrar uma execução antecipadamente, retorne um valor verdadeiro em `on_iteration`.

- `OSError` (embutida) quando `case_dir` não existe.
- `ValueError` (embutida) quando `threads` é `0`, ou quando `config_overrides` está malformado.
- As classes listadas para [`novomodelo.Study`](#novomodelostudy), [`novomodelo.Study.train`](#novomodelostudytrain) e [`novomodelo.Study.simulate`](#novomodelostudysimulate), conforme a fase que falhar.
- Qualquer exceção levantada pelo callback, relançada sem alteração depois que os artefatos são gravados.

### `novomodelo.results.load_results`


## `novomodelo.errors`

Toda classe-folha é subclasse de `novomodelo.errors.NovomodeloError` e de uma exceção embutida, e seu `__module__` é `novomodelo.errors`. A própria `NovomodeloError` é subclasse direta de `Exception` e reporta `__module__` como `errors`. Para as mensagens e códigos de saída de cada tipo, veja [Códigos de erro](/pt-br/reference/error-codes/); para saber qual caminho de carga da política levanta qual classe, veja [Erros de carga da política](/pt-br/reference/error-codes/#erros-de-carga-da-politica).

### `novomodelo.errors.NovomodeloError`

```python
class NovomodeloError(Exception): ...
```

A classe base de todas as exceções do Novo Modelo. Capture a classe tipada para um tipo de falha, a base embutida (`ValueError`, `OSError`, `RuntimeError`) para manter o tratamento no estilo das exceções embutidas, ou `NovomodeloError` para todas elas.

### `novomodelo.errors.ValidationError`

```python
class ValidationError(NovomodeloError, ValueError): ...
```

Os dados do caso ou a configuração falharam na validação. Levantada para um erro da classe de entrada inválida, qualquer que seja o prefixo da mensagem (inclusive um `policy.path` recusado, um diretório de política anterior ausente e uma gravação de checkpoint recusada por causa de seu manifesto ou de uma entrada estranha), para os prefixos de mensagem `config override error`, `config parse error`, `config read error` e `setup validation error`, e para falhas de interpretação, de esquema e de restrição nos dados do caso. Também abrange um arquivo do caso ausente ou ilegível.

### `novomodelo.errors.PolicyIncompatibleError`

```python
class PolicyIncompatibleError(NovomodeloError, ValueError): ...
```

Uma política é incompatível com o sistema ou a compilação atual. Levantada para um erro da classe de política incompatível: um checkpoint de partida a quente, retomada ou somente simulação recusado por causa de seu software, de sua versão ou de uma verificação de contrato que falhou; um checkpoint de fronteira recusado por causa de seu software ou de sua versão; um arquivo de checkpoint de partida a quente, retomada ou somente simulação ausente ou que não pode ser decodificado; e uma falha na construção da FCF.

### `novomodelo.errors.CaseIoError`

```python
class CaseIoError(NovomodeloError, OSError): ...
```

Uma falha de leitura ou gravação no sistema de arquivos durante a carga ou a gravação de um caso. Levantada para os prefixos de mensagem `output write error` e `policy checkpoint error`. Também abrange uma leitura de checkpoint da política que o sistema operacional recusa.

### `novomodelo.errors.OutputError`

```python
class OutputError(NovomodeloError, OSError): ...
```

Uma falha de serialização ou de esquema de saída, levantada por `novomodelo.write_policy_checkpoint`, `novomodelo.results.load_policy` e por uma gravação de checkpoint periódico durante o treinamento. Um erro de E/S do tipo "não encontrado" levanta a exceção embutida `FileNotFoundError`, e os demais erros de E/S levantam `CaseIoError`. Uma falha de manifesto ou uma entrada estranha levanta `ValidationError`, e não `OutputError`.

### `novomodelo.errors.SolverError`

```python
class SolverError(NovomodeloError, RuntimeError):
    stage: int | None
    iteration: int | None
    scenario: int | None
```

Uma falha de treinamento ou do solver. Um erro da classe do solver ou interna levanta `SolverError`, assim como uma mensagem cujo prefixo não é reivindicado por nenhuma outra classe; uma falha da simulação levanta `SimulationError`. Os três atributos estão sempre presentes. Em um subproblema inviável, eles contêm as coordenadas inteiras da inviabilidade; em qualquer outra falha, são `None`.

| Campo | Tipo | Descrição |
| --- | --- | --- |
| `stage` | `int \| None` | O estágio do subproblema inviável. |
| `iteration` | `int \| None` | A iteração do treinamento do subproblema inviável. |
| `scenario` | `int \| None` | O cenário do subproblema inviável. |

### `novomodelo.errors.SimulationError`

```python
class SimulationError(NovomodeloError, RuntimeError): ...
```

Uma falha na fase de simulação. Levantada para o prefixo de mensagem `simulation error`.

## `novomodelo._types`

Os nomes em `novomodelo._types` são classes `TypedDict` usadas apenas para tipagem, correspondentes aos dicts que `novomodelo.run.run` e as propriedades de `novomodelo.Study` retornam; um verificador de tipos os lê a partir dos stubs do pacote. `import novomodelo._types` levanta `ModuleNotFoundError` em tempo de execução, e `novomodelo.StochasticSummary`, `novomodelo.HydroModelsSummary`, `novomodelo.ProvenanceReport` e `novomodelo.System` são, da mesma forma, reexportações existentes apenas nos stubs, ausentes em tempo de execução. Importe os nomes sob `typing.TYPE_CHECKING` e acesse a classe de sistema em tempo de execução como [`novomodelo.model.System`](#novomodelomodelsystem).

```python
from __future__ import annotations

from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from novomodelo._types import RunResult


def final_lower_bound(result: RunResult) -> float:
    return result["lower_bound"]
```

`StochasticSummary`, `HydroModelsSummary` e `ProvenanceReport` são declarados com `total=False`; os dicts que o pacote retorna contêm todas as chaves listadas.

### `novomodelo._types.RunResult`

| --- | --- | --- |
| `converged` | `bool` | `True` quando os critérios de parada encerraram o treinamento e uma regra `gap` ou `bound_stalling` foi acionada nessa iteração. `False` para qualquer outro motivo de parada e para uma execução sem treinamento. |
