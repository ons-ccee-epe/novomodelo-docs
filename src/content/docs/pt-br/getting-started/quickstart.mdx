Esta página leva você do zero a um estudo de PDDE (SDDP) concluído em três comandos, usando o
modelo embutido `1dtoy`. O modelo representa um sistema hidrotérmico com um único barramento,
uma usina hidrelétrica e duas unidades termelétricas, ao longo de um horizonte de planejamento finito de 4 estágios — pequeno
o bastante para rodar em segundos e completo o bastante para demonstrar cada etapa do fluxo de trabalho.

Se você ainda não instalou o Novo Modelo, comece pela [Instalação](/pt-br/getting-started/installation).

![Demonstração do guia rápido](/getting-started/quickstart.gif)

## Passo 2: valide o caso

```bash
novomodelo validate my_first_study
```

O processo de validação verifica todas as camadas — esquema, referências, viabilidade
física e consistência estocástica — e então
monta o estudo como `novomodelo run` faz e verifica qualquer política que a execução carregaria,
sem resolver nenhum PL, e imprime, em caso de sucesso, uma única linha com a contagem de entidades:

{/* capture: novomodelo validate my_first_study | novomodelo   v0.20.0 | binary: novomodelo-cli sha256 ae88209f | case: 1dtoy (novomodelo init --template 1dtoy) */}

```
Valid case: 1 buses, 1 hydros, 2 thermals, 0 lines
```

Essa é toda a saída para um caso sem avisos; um caso que gera avisos
acrescenta um resumo `Validation: 0 errors, N warnings in <dir>` e uma linha `warning:`
por ocorrência. Se alguma camada falhar, o Novo Modelo imprime um resumo
`Validation: N errors, 0 warnings in <dir>` seguido de cada erro
prefixado com `error:`, e termina com código diferente de zero: `1` para um caso recusado, `2` para um arquivo de árvore de aberturas declarado mas ausente
(veja [Referência da CLI — Códigos de saída](/pt-br/reference/cli-reference/#codigos-de-saida)). O modelo 1dtoy sempre passa
na validação.

## Passo 3: execute o estudo

```bash
novomodelo run my_first_study --output my_first_study/results
```

uma simulação final (100 cenários). A saída é gravada em `my_first_study/results/`.

## O que você acabou de executar

O caso `1dtoy` tem um barramento cuja demanda não atendida (déficit) custa `7500 $/MWh`. A usina hidrelétrica
`UHE1` tem um reservatório de 1000 hm³ que começa com 83,222 hm³ e turbina até 50 m³/s com
1 MW por m³/s. As usinas termelétricas `UTE1` e `UTE2` fornecem 15 MW cada, a 5 e 10 `$/MWh`.
A demanda é constante, de 75 MW.

O horizonte tem quatro estágios mensais, do estágio 1 (janeiro de 2024) ao estágio 4 (abril de 2024), com
um patamar de carga cada. Cada estágio sorteia dez aberturas de afluência (`num_openings`) a partir das
estatísticas sazonais em `scenarios/` (média de 40 m³/s), sem defasagens autorregressivas. A taxa
de desconto anual é 0,12.

Os arquivos de configuração e as saídas identificam os mesmos estágios pelo `stage_id` declarado,
de 0 a 3 aqui; os arquivos da política `000.bin` … `003.bin` são numerados a partir de 0 na ordem dos estágios.
Veja [Indexação dos estágios](/pt-br/overview/notation-conventions/#indexacao-dos-estagios).

Para uma iteração da PDDE resolvida à mão em um sistema com um reservatório, veja o
[Exemplo didático de PDDE com um reservatório](/pt-br/examples/toy-single-reservoir/); o
[Exemplo didático de PDDE com quatro reservatórios](/pt-br/examples/toy-four-reservoir/) o estende a quatro
reservatórios.

### Como ler o resumo

- **Unidades.** O limite inferior, o limite superior e o custo esperado são, cada um, um total
  esperado para todo o horizonte: os custos dos quatro estágios, descontados para o início do estágio 1,
  na moeda dos custos do caso. Apesar do rótulo `$/stage`, nenhum deles é um
  valor por estágio.
- **Faixa.** O número após `+/-` na linha `Upper bound` é o desvio-padrão dos
  custos das simulações forward daquela iteração. Com `forward_passes: 1` há um custo por
  iteração, de modo que a dispersão é zero e a linha imprime `+/- 0.00000e0`. Na
  linha `Expected cost`, `+/-` é a semiamplitude do intervalo de confiança de 95 % para a
  média e `std` é o desvio-padrão dos custos dos cenários.
- **Gap negativo.** O limite superior é o custo da única trajetória amostrada na iteração.
  O [gap de otimalidade](/pt-br/math/stopping-rules/#gap-de-otimalidade) é esse custo menos o limite
  inferior, relativo ao limite inferior, de modo que uma trajetória mais barata que o limite inferior produz um
  gap negativo. A maioria das trajetórias deste caso custa cerca de 6e5; as que ficam sem
  água pagam o custo de déficit, chegando a cerca de 2e8 ao longo das 128 iterações. A última
  iteração sorteou uma barata. Com simulações forward amostradas, o gap é uma estimativa, não uma
  garantia.
- **Limite inferior acima da média simulada.** O
  [limite inferior](/pt-br/math/upper-bound-evaluation/#limite-inferior) é o valor esperado do primeiro estágio
  sobre suas dez aberturas, com os cortes treinados. O custo esperado é a média de 100
  cenários sorteados das mesmas dez aberturas por estágio. O desvio-padrão deles
  (2,92909e7) é mais que o dobro da média: a maioria dos cenários é barata e alguns são muito
  caros, de modo que uma média de 100 cenários frequentemente fica abaixo do custo esperado que estima,
  e o limite inferior nunca excede esse custo esperado. Um valor maior de
  `simulation.selection.num_scenarios` estreita o intervalo.
- **Reprodutibilidade.** Os limites, o gap, o custo esperado e as contagens de linhas da política e
  de resoluções de PL são os mesmos em toda execução; apenas os tempos variam conforme a máquina. As
  dez aberturas de afluência e os sorteios dentro da amostra (in-sample) usam a semente `training.tree_seed` (não definida
  no modelo, de modo que se aplica o padrão 42). `training.scenario_source.seed` define a semente apenas dos sorteios fora da amostra (out-of-sample),
  que este caso não usa; [Resolução das sementes](/pt-br/running/configuration/#resolucao-das-sementes)
  descreve ambas as sementes. Alterar `training.tree_seed`, o critério de parada ou
  `forward_passes` altera os limites. O formato completo do
  resumo, incluindo o bloco `Time split`, está documentado em
  [Referência da CLI — Formato da saída](/pt-br/reference/cli-reference/#formato-da-saida).

## Passo 4: leia os resultados

O histórico de convergência e os custos da simulação são arquivos Parquet comuns. Instale
`polars` e `matplotlib` com
`pip install polars matplotlib` e execute os trechos a partir do diretório que contém
`my_first_study/`. O primeiro imprime as três últimas iterações de
`training/convergence.parquet` e resume os custos por cenário em
`simulation/costs/`:

{/* capture: python read results (polars) | novomodelo-python 0.20.0 (PyPI wheel sha256 313393a1) | python 3.12.3 | case: output of novomodelo run (novomodelo-cli sha256 ae88209f) on 1dtoy (novomodelo init --template 1dtoy) */}

```python
import polars as pl

conv = pl.read_parquet("my_first_study/results/training/convergence.parquet")
print(conv.select("iteration", "lower_bound", "upper_bound", "gap_percent").tail(3))

costs = pl.read_parquet("my_first_study/results/simulation/costs/")
per_scenario = costs.group_by("scenario_id").agg(
    (pl.col("discount_factor") * pl.col("immediate_cost")).sum().alias("cost")
)
print(per_scenario.select(
    pl.col("cost").mean().alias("mean"),
    pl.col("cost").median().alias("median"),
    pl.col("cost").max().alias("max"),
))
```

A última linha repete os limites e o gap do resumo, e a média é o custo esperado
do resumo; a mediana mostra que a maioria dos cenários é barata e o máximo, que alguns são muito

custo de um cenário neste caso é a soma, ao longo dos estágios, de `discount_factor * immediate_cost`; `total_cost`
também inclui a estimativa de custo futuro, de modo que somá-lo não reproduz o custo esperado.

O segundo trecho traça os dois limites em função do número da iteração. Ele grava
`convergence.png` no diretório de trabalho, portanto roda sem tela:

{/* capture: python plot convergence (matplotlib) | novomodelo-python 0.20.0 (PyPI wheel sha256 313393a1) | python 3.12.3 | case: output of novomodelo run (novomodelo-cli sha256 ae88209f) on 1dtoy (novomodelo init --template 1dtoy) */}

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
import polars as pl

conv = pl.read_parquet("my_first_study/results/training/convergence.parquet")
fig, ax = plt.subplots()
ax.plot(conv["iteration"], conv["lower_bound"], label="lower bound")
ax.plot(conv["iteration"], conv["upper_bound"], label="upper bound (one forward pass)")
ax.set_yscale("log")
ax.set_xlabel("iteration")
ax.set_ylabel("expected cost")
ax.legend()
fig.savefig("convergence.png")
print("saved convergence.png")
```


Em `convergence.png`, no eixo logarítmico, o limite inferior sobe a partir de 1,23e7 e se estabiliza perto de 2,06e7, enquanto o
limite superior de uma única simulação forward fica perto de 6e5 na maioria das iterações, com picos de até 1,99e8.

## Passo 5: reduza o ruído de amostragem

O limite superior no Passo 3 vem de uma simulação forward por iteração e o custo esperado,
de 100 cenários; portanto, ambos são estimativas ruidosas. Duas chaves de `config.json` controlam esse
ruído: `training.selection.forward_passes`, o número de trajetórias amostradas em cada
iteração, e `simulation.selection.num_scenarios`, o número de cenários simulados.
Defina esses dois valores em `my_first_study/config.json` e mantenha todas as demais chaves; este
trecho mostra os dois objetos:

```json
{
  "training": { "selection": { "method": "sampled", "forward_passes": 10 } },
  "simulation": { "selection": { "method": "sampled", "num_scenarios": 2000 } }
}
```

Execute o estudo novamente em um segundo diretório de saída, para que os resultados do Passo 3 continuem
disponíveis para comparação. A simulação de 2000 cenários grava cerca de 10.000 arquivos, aproximadamente 70 MB:

```bash
novomodelo run my_first_study --output my_first_study/results-more
```

O resumo pós-execução, em trecho (os tempos variam conforme a máquina):

{/* capture: novomodelo run my_first_study --output my_first_study/results-more 2>&1, excerpt | novomodelo   v0.20.0 | binary: novomodelo-cli sha256 ae88209f | case: 1dtoy (novomodelo init --template 1dtoy) + config.json training.selection.forward_passes 10, simulation.selection.num_scenarios 2000; timings vary */}

```text
  Upper bound:  1.73930e7 +/- 2.30248e7 $/stage
```

Com esses valores, o limite superior de cada iteração é a média de dez custos de trajetória, impressa
com seu desvio-padrão, e o gap (-15,64066 % na última iteração) continua sendo uma
estimativa que varia de iteração para iteração. O custo esperado dos 2000 cenários é
um intervalo de confiança de 95 %, `2.16935e7 +/- 1.92862e6`, que contém o limite inferior; assim, os dois concordam
dentro do ruído de amostragem. O limite inferior termina ligeiramente acima do Passo 3, em `2.06178e7`,
com dez
cortes adicionados por estágio em cada iteração (3840 linhas da política: 128 iterações, dez cortes para cada
um dos três estágios que recebem cortes). Um gap exato, e o critério
de parada `gap`, exigem seleção forward enumerada, que as dez aberturas por estágio deste caso não
admitem; [Convergir até um gap](/pt-br/running/configuration/#convergir-ate-um-gap)
apresenta a configuração.
